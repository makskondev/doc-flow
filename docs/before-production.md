# До продакшена

## Что нужно доделать

1. **`ApplyStampStep.Stamp`** (`Documents/Zop`) — сам штамп. Обычный шаг сервиса, код пишет разработчик; сейчас заглушка
   (дописывает маркер, PDF визуально не меняется). Выбор PDF-библиотеки за вами; учтите условия лицензий
   (например, у PDFsharp и iText они разные — проверьте актуальные).
2. **Описания вьюх** (`Documents/Views/View1Reader.cs`, `View2Reader.cs`) — по одному на вьюху: `SELECT` (id документа, путь к файлу —
   если вьюха его отдаёт, и колонки в `Data`: признак вида документа для правил `Matches`, поля для штампа). Сейчас читатели
   возвращают пустой список. Названия колонок (`DataKeys`) и значения `DocKind` в правилах маршрутов — примеры.
3. **`IExternalDocumentDb`** (сейчас заглушка в памяти) — три операции над сторонней БД: регистрация документа (идемпотентна
   по `processId`), «завершён ли», «сохранить подпись и поставить отметку» одной транзакцией.
4. **`ISigningService`, `ISignatureVerifier`** — клиенты REST-сервиса подписи и API проверки.
5. **`IEscalationNotifier`** — отправка письма (сейчас пишет в лог).
6. **Миграции:** создать `InitialCreate` и закоммитить (см. `docs/operations.md`).
7. **Безопасность:** операторский API без аутентификации; `Data` содержит персональные данные; пароль из `appsettings.json` убрать в окружение.
8. **Один экземпляр.** Для нескольких нужна распределённая блокировка вместо `ProcessLocks` (optimistic lock в репозитории уже есть).

Все заглушки лежат в `Host/Infrastructure/Stubs`; подключаются в `Host/Composition/HostServiceCollectionExtensions.cs`
(раздел «ЗАГЛУШКИ — заменить»).

## Допущения, которые стоит проверить

* **Имена в каталогах подписания.** Файл кладётся в папку для подписи как `{processId}.pdf`; система подписания должна
  положить в директорию результата `{processId}.pdf` и `{processId}.sig` (имена сохраняются).
* **Подпись отсоединённая.** Проверка подписи сверяет хеш PDF с тем, что отправлен на подпись. Если процесс подписания
  перезаписывает PDF, ослабьте проверку в `VerifySignatureStep`.
* **Имя в конечном каталоге** — исходное имя файла, подпись — «имя.pdf.sig»; чужой файл с тем же именем не перезаписывается (эскалация).
* **Оригиналы на чужой шаре не удаляются** (файл копируется в рабочий каталог, затем переносится дальше). Каталоговый источник
  переносит оригинал в `_processed`.
* **Идентификатор документа во внешней БД** для документов из вьюх — идентификатор записи вьюхи (`ExternalId`); для документов
  из каталогов — идентификатор, выданный `RegisterDocumentAsync`.
* **Поиск файла** (`FindFileStep`): по умолчанию имя берётся из колонки `FileName` либо `{id}.pdf`, каталог — `SearchDir`.
* **Штамп в сценарии 1** оставлен, потому что вы описывали его ранее; если в этом типе его нет — уберите шаг `ApplyStampStep` из `ZopRoute`.
* Файл считается готовым, когда размер и время записи не менялись между двумя опросами (`Engine:PollIntervalSeconds`, `SignalScanIntervalSeconds`).
* Аудит пишется синхронно и не атомарно с состоянием процесса; при сбое записи событие теряется (только лог).

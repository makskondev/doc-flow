# Эксплуатация

## Конфигурация (`DocFlow.Host/appsettings.json`)

| Секция | Что настраивает |
|---|---|
| `ConnectionStrings:DocFlow` | подключение к PostgreSQL. В окружении — переменная `ConnectionStrings__DocFlow` или user secrets |
| `Database:MigrateOnStartup` | применять миграции при старте (выключите, если миграции накатывает отдельный процесс деплоя) |
| `Engine` | интервалы опроса источников/сигналов/раннера, число попыток и задержка повтора, параллелизм |
| `Storage` | `WorkingDir` и каталоги по типам документов: `Types:<тип>` → `SignInputDir`, `SignResultDir`, `FinalDir`, `SearchDir` |
| `Intake:Directories` | каталоги приёма: `Name` (логическое имя), `Path`, `Mask`. Тип документа определяют правила `Matches` маршрутов |

## База данных и миграции

```bash
dotnet tool install --global dotnet-ef
dotnet ef migrations add <Имя> --project src/DocFlow.Data --startup-project src/DocFlow.Host
```

Папка `src/DocFlow.Data/Migrations` создаётся командой и коммитится. При изменении модели (`DocFlowDbContext`) добавляйте
новую миграцию. Для `dotnet ef` строку подключения можно задать переменной `DOCFLOW_CONNECTION`
(по умолчанию — локальная из `docker-compose.yml`). Если миграций в проекте нет, сервис падает при старте с подсказкой.

## Операторский API

| Запрос | Действие |
|---|---|
| `GET /processes?status=NeedsAttention` | список процессов (фильтр по статусу — необязательный) |
| `GET /processes/{id}` | процесс и журнал его событий |
| `POST /processes/{id}/retry` | повторить текущий узел (для ожидания — снова встать в ожидание с новым таймаутом) |
| `POST /processes/{id}/continue` | пропустить текущий узел (осознанное решение оператора) |
| `POST /processes/{id}/cancel` | отменить процесс |
| `POST /processes/{id}/restart` | перезапустить **отменённый** процесс (новый `Run` с прежними данными) |

`retry` и `continue` работают только для `NeedsAttention`. ⚠️ API сейчас без аутентификации, а ответ содержит входные
данные документа (персональные данные).

## Разбор эскалации

1. Приходит письмо: id процесса, документ, узел, причина (`AttentionReason`).
2. `GET /processes/{id}` — причина и журнал событий.
3. Причину устранили (сервис подписи поднят, файл на месте, подпись пришла после таймаута) → `retry`.
4. Узел заведомо не нужен → `continue`. Документ не нужен → `cancel`.
5. Данные во вьюхе исправили, а процесс уже отменён → дождитесь, пока запись вернётся в обработку: `restart` берёт прежние данные.

## Что смотреть в логах

* `Документ ... не зарегистрирован: во входных данных нет полей` — во вьюхе неполные данные (предупреждение пишется один раз).
* `Документ ... не распознан: ни одно правило Matches не подошло` — документу не нашёлся маршрут (запись остаётся в источнике).
* `Документу ... подходит несколько маршрутов` — правила `Matches` пересекаются; документ не регистрируется, пока их не уточнят.
* `Для типа документа ... не настроен каталог ...` — не заполнена секция `Storage:Types:<тип>` (эскалация процесса).
* `ЭСКАЛАЦИЯ: ...` — заглушка письма (пока реальная отправка не подключена).
